# UCP 2026-08-25: Move the Server Gems Up a Spec Revision

**Status:** Phase 1 done. The CLI's agent profile already moved (`keys`, capability `spec`/`schema`); this plan covers `portage-ucp` and the adapter gems.

**Driver:** `portage-ucp` pins UCP 2026-04-08 ([manifest.rb:13](../../portage-ucp/lib/portage/ucp/manifest.rb#L13)) while the latest release is [v2026-08-25](https://github.com/Universal-Commerce-Protocol/ucp/releases) and live Shopify stores already serve it ([well-known-ucp.md](../well-known-ucp.md)). A strict 2026-08-25 client reading our manifest won't find our signing keys and may reject or down-negotiate us.

## Where 2026-04-08 is pinned

- `Manifest::UCP_VERSION` ([manifest.rb:13](../../portage-ucp/lib/portage/ucp/manifest.rb#L13))
- `WireEnvelope::SPEC_VERSION` ([wire_envelope.rb:9](../../portage-ucp/lib/portage/ucp/wire_envelope.rb#L9))
- `SchemaValidator` default `version:` ([schema_validator.rb:17](../../portage-ucp/lib/portage/ucp/schema_validator.rb#L17))
- Signature spec citation ([signature.rb:10](../../portage-ucp/lib/portage/ucp/security/signature.rb#L10))
- Vendored schemas: `portage-ucp/schemas/2026-04-08/`

## Breaking changes that touch us

| 2026-08-25 change | Our exposure |
|---|---|
| `signing_keys[]` removed; `keys[]` (JWK Set) at the document root, beside `ucp` | `Manifest#to_h` nests `signing_keys` *inside* `ucp`. Must move and rename. `Configuration#signing_keys` and the install generator template can keep their names. |
| `fulfillment_option.description` becomes a structured object | `FulfillmentOption#description` ([value_objects.rb:275](../../portage-ucp/lib/portage/ucp/value_objects.rb#L275)) is a plain value today; check what each adapter mapper puts there. |
| Fulfillment flags drop `allows_`; `multi_destination` map → array; method type enum opens to string | No uses found. Re-check against the new schemas. |
| Buyer `consent` becomes a reverse-DNS-keyed map | No uses found. |
| Repo split into Shopping / Payment / Common verticals | Schema `$id`s and `$ref`s may move; the vendoring step and `SchemaValidator` root resolution must follow. |

## Phases

One phase per session, delegated to a Sonnet subagent, each ending with a design-log entry, a commit and a restart prompt.

**Phase 1: vendor the schemas.** Add `portage-ucp/schemas/2026-08-25/` alongside 2026-04-08 (keep the old set for now). Point `SchemaValidator` at it with a spec proving both versions load. Note any moved `$id`s.

**Phase 2: manifest.** Bump `UCP_VERSION`/`SPEC_VERSION`, emit `keys` at the root instead of `ucp.signing_keys`, and make `manifest_spec` validate the document against the 2026-08-25 business profile schema. Update `docs/well-known-ucp.md` (drop the "version runs ahead of this gem" note) and the `portage doctor` signing-keys message if it names the field.

**Phase 3: wire shapes.** Run the conformance kit (`writing-adapters.md`) for the reference adapter and every adapter gem against 2026-08-25. Fix `FulfillmentOption#description` and anything else the validator flags. Check `portage-ucp-client` still reads both versions (stores won't all move at once).

**Phase 4: release.** Drop the 2026-04-08 vendored schemas if nothing references them, changelog every touched gem as a minor bump, cut the release set.

## Out of scope (separate looks later)

Actions/3DS2, `$requestConstraints`, payment schedules and split payments, `policies[]`, shopping permalinks, loyalty, and the grocery additions (location search, operating hours, fractional quantities; see design-log §53).
